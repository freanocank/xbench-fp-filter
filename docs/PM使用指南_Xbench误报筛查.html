01

用途与准备

Purpose & preparation

这份指南覆盖当前公开流程：读取 Xbench 导出的 Excel QA 报告，对错误描述非空的识别行调用大模型判断「真错误 / 误报」，再生成过滤报告与分析表。

平台与能力边界：正式支持平台：Windows 10/11。其他平台未经过正式验证。首次安装和每次大模型筛查都需要网络。当前 UI 是「解析 → LLM 独立判断」，不使用实验中的 RAG 向量案例库；历史 RAG 脚本不属于本指南的日常流程。
当前过滤风险：解析器识别到、但「错误描述」为空的行不会进入 LLM 或 analysis，却仍会被 filtered 静默删除；模型若返回非“真错误 / 误报”的非法标签，该行会在 analysis 显示红色、统计计入 kept，但也会从 filtered 删除。发布硬门槛是：识别数据行数 = 有效复核项数，且非法标签数 = 0；任一不满足，整份文件 FAIL，禁止下发 filtered。
Xbench QA 报告.xlsx → 解析有效 QA 项 → LLM 独立复核 → filtered.xlsx + analysis.xlsx → 人工抽检后下发修正

工作目录与运行前检查

项目PM 需要确认
工作目录进入同时含 run.bat、setup.bat、ui/、core/ 的项目根目录。本文 Agent 指令使用已核验路径：/Users/spellbook/Desktop/Langlobal/xbench-fp-filter。
Windows / 网络准备 Windows 10/11 x64 电脑。首次安装会从 python.org 下载 Python 3.11.9 embedded 并安装依赖；运行时会为每个有效 QA 项调用外部 API。
API / 模型准备兼容 OpenAI Chat Completions 的 API Key、Base URL 与模型 ID。连接测试本身会发出一次短聊天请求；API Key 只在可信本机录入，不放入文档、截图、Agent 提示或交付包。
输入报告准备 Xbench 原样导出的 .xlsx QA 报告，可一次上传多份。不要把普通缺陷表改名为 xlsx 后上传，也不要移动列、删除组标题或改变前 10 行结构。

输入契约：什么会被处理

规则当前实现
工作表选择按工作簿顺序选择名称中含 xbench 或 qa 的第一个工作表；都没有时读取第一个工作表。上传前应确认真正的报告表会被选中。
行与列结构从第 11 行开始识别数据；依赖 A 列组标题与「文件名 (数字)」式数据行，C 列为原文、D 列为译文、E 列为说明。F 列会解析为元数据；F/G 只共同识别「已修改」标记，当前 UI 不把该标记或元数据送入 LLM / analysis。普通表格不符合此契约。
有效 QA 项只有能生成非空「错误描述」的识别行进入 LLM。页面「报错总条数 / 总行数」指有效复核项，不是 Excel 的物理行数。识别行与有效项的差值是未复核行，必须为 0。
批次文件名上传批次内 basename 与去扩展名 stem 均须按不区分大小写唯一。同名会覆盖内存中的原始字节，ZIP 还会出现同名条目；发现重复即 FAIL，先重命名文件副本再上传。
批量与并发多文件按上传顺序逐个处理；单个文件内的 QA 项按设置的并发线程数并发调用 API。并发越高越容易触发限流。

产物分类：哪些能拿走，哪些只是运行状态

产物分类位置与用途
Xbench_Filtered_Results.zip可下载批量包；每个成功文件各含一份 *_filtered.xlsx 和 *_analysis.xlsx。异常或零有效项的文件不会进入 ZIP。
[原名]_filtered.xlsx可下载在原 Xbench 工作簿中只保留标签恰为「真错误」的数据行，并删除变空的组标题。正常「误报」会删除；错误描述为空的未复核行和非法模型标签行也会被删除，这是当前实现风险。常规 API 异常、空响应或响应解析失败会回退为「真错误」并保留。
[原名]_analysis.xlsx可下载「复核结果」工作表，固定 7 列：# / 原文 / 译文 / 错误类型 / 错误描述 / 系统判断 / 复核依据。它是选定复核字段，不是原报告全部列的副本。
页面指标 / 在线明细仅显示处理文件数、有效复核项、过滤数、过滤率及在线预览。清除或结束 Session 后不可恢复，不是交付文件。
上传内容 / 运行结果 / ZIP 缓存临时只保存在当前 Streamlit 进程内存。项目目录不会自动生成固定输出副本，必须从浏览器下载并归档。
config.py / custom_models.json内部前者可能含明文 API Key；后者保存自定义模型列表及预置模型启用 / 禁用状态。两者都不是交付物。RAG 数据、测试报告与 raw_data 也不属于当前 UI 产物。
02

手动启动与完整闭环

Manual operation

安装、设置、筛查与归档

首装（Windows 10/11）。解压完整项目，在根目录先双击 setup.bat。它下载 Windows x64 Python 3.11.9 embedded、安装 pip 与 streamlit / openai / openpyxl，并在缺失时生成 config.py。首次必须联网。
启动。双击 run.bat。它优先使用项目内 Python，其次使用系统 Python；浏览器未自动打开时查看终端给出的本地地址。不要关闭承载 Streamlit 的终端窗口。
配置当前 Session。进入「参数设置」，填写 API Key / Base URL，选择或添加模型，设置 Temperature 与并发线程数。页面改动只对当前进程生效；仅启用 / 自定义模型集合会写入 data/custom_models.json。config.py 提供 API、Base URL、Temperature 与 Max Tokens；其中模型只有仍在启用列表时才作为默认，否则重启后选列表首项。并发不能保存，重启固定回到 24。
测试连接。点「测试连接」。它会向当前模型发送一次最小 Chat Completions 请求，成功表示当时的 Key、Base URL 和模型可用，也可能产生少量 API 费用；失败时不要开始批量任务。
检查输入。确认文件是未改结构的 Xbench .xlsx 导出，真实报告工作表名称含 xbench / qa，或位于第一个工作表。批次内文件名与 stem 按不区分大小写唯一；重复时先重命名副本。保留原文件，不在唯一原件上覆盖保存。
上传并开始。进入「误报筛查」，拖入一份或多份报告，点 ▶ 开始筛查。页面先显示解析进度，再显示大模型复核进度。多文件逐个处理，单文件内部按并发值发出请求；当前没有取消 / 断点续跑。
读懂汇总。「报错总条数」是错误描述非空的有效复核项；识别到但错误描述为空的行不计入页面、却会被 filtered 删除。「拦截误报数」是正常判为误报的数量；「保留错漏」包含真错误、常规 API / 解析失败的保守回退，也会错误计入非法模型标签。文件状态「正常」不代表满足发布门槛。
立即下载。先下载 Xbench_Filtered_Results.zip，再按需下载单文件 *_filtered.xlsx 与 *_analysis.xlsx。文件进入浏览器默认下载目录或提示的用户选择位置；项目内没有固定输出副本。
硬检查后再人工复核。先确认识别行 = analysis 行、系统判断只含两种合法值，再搜索「调用失败」「空响应」「解析失败」并抽检两类判定。任一硬检查失败都禁止下发 filtered；通过后确认被删行确属误报、保留行确需修正，并把 analysis 与原始报告共同归档。
首装纠偏：旧说明称首次双击 run.bat 会自动安装，但电脑已有系统 Python 时脚本不会调用 setup.bat，依赖可能缺失；且缺少 config.py 时会直接退出。可靠首装顺序是先 setup.bat，再 run.bat。

判定与颜色含义

系统判断过滤报告分析表PM 含义
误报删除该数据行绿色填充模型认为 Xbench 初检不成立；这是最需要防止误删真错误的一组。
真错误保留该数据行红色填充模型认为应下发修正；常规 API 异常、空响应或响应解析失败会回退到此组。
空错误描述错误地删除不进入 analysis识别行未接受 LLM 复核；只要出现 1 条，整文件 FAIL。
非法模型标签错误地删除红色填充，统计计入 kept标签不是“真错误/误报”；只要出现 1 条，整文件 FAIL。

04

量化验收

Acceptance checks
关口检查方法通过标准
输入可解析记录工作表、被选工作表、识别数据行、有效项和批次文件名。全部为标准 Xbench .xlsx；basename / stem 不区分大小写唯一；选中正确工作表；识别行 = 有效项 > 0，未复核识别行 = 0。
文件齐全核对输入清单、单文件产物与 ZIP 条目。每个成功输入恰有 filtered + analysis；ZIP 每个成功文件恰含这 2 项；失败输入 = 0，缺失 / 多余 / 重名条目 = 0。
分析表契约打开 analysis 的「复核结果」表并检查表头与判断值。恰为 7 列：# / 原文 / 译文 / 错误类型 / 错误描述 / 系统判断 / 复核依据；判断值只含真错误 / 误报，非法标签 = 0。
数量闭环比较原始解析、页面或 manifest、analysis 与 filtered。识别行 = 有效项 = analysis = total；真错误 + 误报 = total；filtered 有效行 = 真错误 = kept；误报 = suppressed，所有差异为 0。
字段零差异按原始有效项顺序比较 analysis 的原文、译文、错误类型、错误描述。四字段差异数 = 0；不得把 analysis 描述成原报告所有列的完整副本。
删除集合先确认未复核行与非法标签均为 0，再以文件名、segment ID、原文、译文和说明组成多重集比较。filtered 只删除 analysis 判「误报」的数据行；所有「真错误」行都保留；额外删除或漏删 = 0。两个前置门槛不满足时整项直接 FAIL。
失败保留搜索复核依据中的调用失败、空响应和解析失败。自动发布门槛为 0；若大于 0，必须重跑或逐条人工确认，不得把这些保留行计作已确认真错误。
工作簿完整性比较工作表名称、非目标工作表的值 / 公式 / 合并区域，并人工打开 filtered。除预期删除的误报数据行和空组标题外，结构值差异 = 0；文件可正常打开，视觉格式无明显损坏。
人工语义分别抽检误报和真错误；误报组优先检查专名、术语遗漏和上下文省略。被删行确属误报，保留行确需修正；问题有行标识、责任人和处理结论。自动脚本不得替代该结论。
报告口径检查首跑、重试、GT 修订和人工排除是否分栏。首跑与重试不混算；原始标签结果与修订标签结果并列，不用调整后数字覆盖原始数据。

性能数字不是 SLA：仓库历史门槛多次变化，没有一套当前统一阈值。2026-05-21c 的 1000 条测试记录为：准确率 75.8%、误报识别率 73.3%、原始真错误保护率 98.0%；排除 1 条人工确认的 GT 错标后才是“有效 99.0%”。这组数据只说明该批测试，不保证新项目表现。

常见问题与故障恢复

Problems & recovery
run.bat 提示 config.py 不存在
完整运行 setup.bat 让它从模板生成配置，或由授权人员复制 config_template.py 为 config.py。不要把含真实 API Key 的配置放进交付包或版本库。
run.bat 双击无反应，或提示缺 Python / 模块
从项目根目录先运行 setup.bat，确认项目内 python/ 和三项依赖安装成功，再运行 run.bat。电脑已有系统 Python 时，run.bat 不会自动安装；从终端运行可保留原始错误。
setup.bat 下载或安装依赖失败
确认网络可访问 Python 与 pip 下载源、磁盘空间足够，再重跑。不要修改 requirements 或删除半成品来掩盖失败；把下载 Python、安装 pip、安装依赖中的实际失败步骤和脱敏错误交给技术负责人。
提示缺 DLL，embedded Python 无法启动
按《使用说明》安装 Microsoft Visual C++ Redistributable x64，重启工具后再验证。该恢复路径只有手册说明，仓库没有自动兼容性测试；仍失败时保留终端原始错误。
浏览器没有自动打开
保留终端窗口，等待 Streamlit 启动后打开终端显示的本地地址，通常是 localhost:8501。若仍打不开，检查终端是否退出、端口是否冲突，再按实际端口访问。
API 测试失败、401、模型不可用
核对当前 Session 的 Key、Base URL 与模型 ID，确认网络、余额和 Chat Completions 兼容性，再测试。测试会发送真实请求；不要在截图、日志或 Agent 提示中粘贴密钥。
频繁 Rate Limit、超时或运行很慢
在「参数设置」降低并发线程数后，重新运行受影响文件。每条请求最多尝试 5 次，单次超时为 90 秒，连续失败会显著拖长任务。首跑与重试分别统计，不把重试成功回填到首跑指标。
提示“无有效数据行”
确认上传的是标准 Xbench 导出而非普通缺陷表；检查真正报告表是否会按“名称含 xbench/qa，否则首表”规则选中；确认第 11 行以后仍有 A 列「文件名 (数字)」式数据行及非空错误描述。不要通过移动列来适配工具。
识别数据行比页面“报错总条数”多
差值就是错误描述为空、未进入 LLM / analysis 却会被 filtered 删除的识别行。只要差值大于 0，整文件 FAIL，禁止下发 filtered；先列出原始行并交给技术负责人，不要把它们计为误报。
文件显示“正常”，但保留错漏异常多或判断值异常
打开 analysis 搜索「LLM调用失败」「LLM返回空响应」「LLM响应解析失败」，并枚举「系统判断」唯一值。常规单行失败会回退真错误并保留；非“真错误/误报”的值却会计入 kept、显示红色并从 filtered 删除。任一非法值使整文件 FAIL。
批量 ZIP 里少了某个文件
查看页面汇总中的「处理状态」。解析失败、无有效项或 rows 为空的文件会被 ZIP 静默跳过；记录该文件为失败，修复输入后单独重跑。另检查批次是否有不区分大小写的同名 basename / stem；重复时先重命名副本再重新上传，不得把缺失文件解释为 0 个问题。
误点清除、关闭页面或服务后找不到结果
当前 UI 没有历史结果、断点或项目内自动副本；上传内容与产物只在 Session 内存。若未下载只能用相同输入和配置重跑。每轮完成后应先下载 ZIP，再做页面分析。
filtered 打开后格式或公式异常
工具通过 openpyxl 重新保存工作簿，并会删除数据行与空组标题。先确认输入是标准 Xbench 报告；比较工作表、公式、合并区域与视觉格式。原始报告始终单独留档，发现非预期变化就停止下发。
参数重启后恢复默认，或误以为用了案例库
UI 参数改动不持久化。API、Base URL、Temperature 与 Max Tokens 重启后从 config.py 读取；模型仅在配置值仍属于启用模型集合时生效，否则选列表首项。要持久指定模型，先确保它未被禁用或已加入模型集合，再由授权人员修改 config.py。并发始终重置为 24。当前 UI 固定传空历史案例，RAG 数据不会参与本轮判断。
恢复原则：保留原始 Xbench 报告、首跑 analysis / filtered / ZIP 和脱敏错误；先定位安装、解析或 API 阶段，再只重跑受影响文件。重试结果与首次运行分开记录。
